# MOVER — المعمارية المقترحة

هذه توصية تصميمية، وليست وصفاً لخادم منفذ في النموذج. يتحقق المنفذ من توافق الإصدارات قبل تثبيتها.

## التكوين المقترح

| المكوّن | الاختيار المبدئي | المسؤولية |
|---|---|---|
| الواجهة | React + TypeScript + Vite | واجهة عربية RTL، نماذج، خرائط، مهام، واستوديوهات إعداد |
| الخرائط | Leaflet كبداية؛ تقييم MapLibre/OpenLayers عند توفر ملفات الخرائط | عرض مصادر محلية؛ لا خدمة عامة لازمة للإنتاج |
| تطبيق الخلفية | Spring Boot كتطبيق وحدات داخل مشروع واحد | قواعد الطلبات والحجوزات والملفات والتدقيق والتكامل |
| الإجراءات | Flowable Open Source مضمناً في الخلفية | BPMN/المهام/المهل/المراجعات/إصدارات التشغيل |
| الهوية | Keycloak محلي أو تكامل داخلي مع الهوية المعتمدة | تسجيل الدخول والجلسات وتوثيق المستخدم |
| التفويض | OpenFGA محلي | علاقات المستخدم والجهة والموقع والمورد ونطاقات الوصول |
| البيانات | PostgreSQL + PostGIS إذا كانت هندسة المواقع مطلوبة | بيانات الأعمال والفترات والهندسة والفهارس |
| المرفقات | مخزن ملفات محلي خلف واجهة تخزين | ملفات فعلية وإصداراتها وصلاحيات تنزيلها |
| إشعارات ومعالجة غير متزامنة | عامل محلي + transactional outbox | إشعارات قابلة للإعادة دون فقد أو تكرار أثر |
| الدخول الموحد للويب | وكيل عكسي داخلي | TLS والتوجيه وحدود الأحجام |

لا نحتاج تقسيم كل وحدة إلى خدمة مستقلة من البداية. يمكن تشغيل نسخ متعددة من التطبيق لاحقاً بحسب القياس، مع هوية وقاعدة بيانات ومخزن ملفات مشتركين بطريقة مدروسة.

## الوحدات داخل الخلفية

`identity-adapter`, `organization`, `facilities`, `requests`, `forms`, `workflow`, `reservations`, `approvals`, `execution`, `attachments`, `authorization`, `audit`, `reporting`, `integrations`.

تُفصل واجهات الوحدات عن جداولها الداخلية. لا تقرأ الواجهة جداول Flowable أو OpenFGA مباشرة، ولا تتصل بالقاعدة أو بمخزن الملفات دون تطبيق فحص الوصول.

## الاعتماد والحجز: حدود المعاملة

التوصية تضمين Flowable واستخدام مدير معاملة متوافق مشترك حيثما يسمح التوافق المختار. أثبت عملياً أن قرار الخطوة النهائية وتثبيت حجز المورد وحفظ القرار وحدث outbox لا تنفصل عند فشل جزئي.

على قاعدة البيانات منع تداخل الفترات للحجوزات النشطة الحصرية، باستخدام إمكانات الفترات والقيود المناسبة. عند طلب عدة موارد تُثبت جميعها أو لا يُثبت أي منها. يُعاد خطأ `RESERVATION_CONFLICT` قابل للفهم، ولا تُنشأ مرحلة مراجعة جديدة تلقائياً؛ يمكن للمراجع إرجاع الطلب بحسب صلاحياته.

إذا اختير فصل Flowable إلى خدمة لاحقاً، يجب إعادة تصميم حد المعاملة والتعويض والمصالحة صراحة، لا افتراض أن معاملتين عبر HTTP صارتا ذريتين.

## الصلاحيات ومصدر الحقيقة

- مصدر العضويات والأدوار المؤرخة هو سجل المؤسسة المعتمد.
- سياسات OpenFGA لها إصدارات ومخطط واضح لعلاقات الجهات والمواقع والطلبات.
- يوجد مسار موثوق لمزامنة تغييرات العضويات والتفويضات؛ يُختبر السحب الفوري أو المحدد زمنياً وفق سياسة معلنة. عند الشك أو فشل التحقق لا يمنح الوصول.
- القوائم والبحث والخرائط والتصدير والمرفقات تستخدم النطاق نفسه. تُحجب البيانات في الاستعلام أو في طبقة الخادم قبل الإرسال.
- نتائج العدادات لا تكشف عدد أو هوية موارد خارج النطاق.
- صلاحية اعتماد الطلب تتحقق وقت القرار، إضافة إلى تحقق إسناد المهمة وصفة الشخص وتفويضه.

## النماذج والتدفقات

تعريف النموذج JSON مضبوط بمخطط تحقق ومعرفات حقول ثابتة وقواعد مقيدة. لا يسمح باستدعاءات شبكية أو استعلامات SQL أو JavaScript من الحقول.

استوديو التدفقات ينتج تعريف BPMN صالحاً ويحتفظ بملفاته وإصداراته. يمكن استخدام `bpmn-js` كمحرر مع مراعاة ترخيصه وإبقاء العلامة المطلوبة. Flowable هو المحرك؛ المحرر وحده لا ينفذ إجراءات الأعمال أو الصلاحيات.

يُثبت كل طلب على إصدار النموذج والتدفق والسياسات ذات الأثر الإجرائي وقت التقديم. تغيير تعريف منشور ينشئ إصداراً جديداً. ترحيل الطلب القائم إجراء منفصل له أثر وتفويض واختبارات.

## النشر المعزول

- `compose` مناسب لتطوير وتجربة أولية موثقة؛ لا يثبت وحده تحمل الأعطال أو الحمل المطلوب.
- ثبّت صور الحاويات والإصدارات، واحفظ سجل المواد البرمجية والتراخيص.
- جهّز صوراً وحزماً وخطوطاً وخرائط ووثائق قابلة للنقل إلى البيئة المعزولة بطريقة معتمدة.
- لا تعتمد على تنزيل `npm` أو `Maven` أو جلب صور Docker من الإنترنت عند تشغيل البيئة المعزولة.
- اجعل الاتصالات الداخلية معلنة، واقصر المنافذ المنشورة على نقاط الدخول المطلوبة. شبكة Docker الافتراضية وحدها لا تعني انعدام الاتصال الخارجي؛ تُختبر سياسة الخروج على مستوى البيئة.
- لا توجد تحليلات سحابية أو CDN أو جلب صور جوية أو تحقق شهادات عبر الإنترنت كاعتماد خفي.
- حزم الخرائط لها فهرس تغطية وإصدارات ومصدر وترخيص. لا يُفهم «نطاق غير محدد» على أنه تنزيل جميع الخرائط التفصيلية للعالم.
- تُثبت جهة الثقة والشهادات والساعة الداخلية وطريقة تحديثها وفق متطلبات المؤسسة.

## النسخ والاستعادة والمراقبة

نسخ مترابطة لبيانات الأعمال، وهوية المستخدمين، وسياسات التفويض، وتعريفات الإجراءات والنماذج، والمرفقات، وبيانات الخرائط وتهيئتها. تُختبر استعادة إلى بيئة نظيفة مع تطابق القرارات والملفات المرتبطة.

راقب محلياً زمن API، فشل تسجيل الدخول، أخطاء الصلاحيات، تعارض الحجز، تأخر مهام المراجعة، وتأخر outbox. لا تسجل محتوى المرفقات أو الرموز السرية في السجلات.

أهداف RPO/RTO والتزامن وحدود زمن الاستجابة وبيئة التوافر العالي غير محددة بعد. اقترح ملفات اختبار واضحة وأعد القياس عند اعتماد القيم.
