# بيانات قبول مؤقتة داخل التطبيق الواحد على :8088

قرار المالك (7 نوفمبر 2026): يجري القبول على `http://localhost:8088` نفسه، بلا منفذ آخر. كل ما يدخل هنا وهمي، ورموزه تبدأ بـ`ACC-20261107-`، وأسماؤه تحمل «اختبار قبول — وهمي».

## الإدخال

```sh
OUT=$(sh ops/backup.sh | tail -1)
sh ops/acceptance-main/provision.sh "$OUT"
```

يتوقف الإدخال إن لم ينجح `ops/verify-backup.sh` على النسخة، أو إن كانت بيانات قبول محمّلة أصلاً.

**ما يتغير في التطبيق أثناء التحميل:**

- **مزامنة Oracle متوقفة** (`hr_source.enabled = false`). لو عملت لأحالت الوحدات الوهمية إلى التقاعد لأنها ليست في Oracle.
- **سياسة تمركز قبول** منشورة ومعمول بها، ومرجعها `ACCEPTANCE / FICTIONAL`. ليست قيم الإنتاج.
- **مسار «طلب صلاحيات» مفعّل** بنسخة قبول. مسودتك محفوظة في ملف التشغيل وتعود عند الإزالة.
- **ثلاث صلاحيات إضافية** يضيفها مدير صلاحيات الوحدة. الأربع المعروضة لكل شخص جديد لم تتغير.

## الإزالة

```sh
node ops/acceptance-main/cleanup.mjs --dry-run   # يعرض ما سيُزال، ولا يغيّر شيئاً
node ops/acceptance-main/cleanup.mjs
```

**كيف تعمل:** تبدأ من معرّفات الوحدات والأشخاص والمواقع في ملف التشغيل، وتتبع كل صف يشير إليها، وتكتب القائمة الدقيقة في الملف قبل أي حذف. وترفض المتابعة إن وصلت إلى جدول إعدادات حقيقي أو إلى شخص أو وحدة خارج الملف.

**ما يُزال:** تلك الصفوف، وسجلات Flowable الخاصة بها، وصفوف HR الوهمية، ومدخلات الدليل، ومستخدمو Keycloak الوهميون. ويعود مسار الصلاحيات إلى مسودته، وتعود مزامنة Oracle إلى حالتها.

**ما يبقى عمداً:** صفوف `audit_event`، لأن السجل لا يُحذف منه. تميّزها أسماء الأشخاص، وسطرا `ACCEPTANCE_RUN_LOADED` و`ACCEPTANCE_RUN_CLEANED` اللذان يحددان نطاقها بالوسم `ACCEPTANCE / FICTIONAL`.

**التحقق بعدها:** تقارن عدد الصفوف وبصمتها في كل جدول مع ما كانت عليه قبل التحميل، وعدد صفوف الصلاحيات في OpenFGA، وتعيد رمز خروج 1 عند أي فرق. لا تُقارن: سجل التدقيق، ومتابعة مزامنة الصلاحيات، وجلسات الدخول، وسجلات منع التكرار، وسجل الترحيلات.
