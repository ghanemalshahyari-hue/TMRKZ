Keycloak
--------
tmrkz/keycloak:26.7.5-2 is built from TMRKZ's own ops/keycloak/Dockerfile (Keycloak 26.7.5 with the TMRKZ theme and
the TMRKZ realm), not an unrelated upstream image. On every start the step keycloak-setup applies the current settings
from the folder and .env: sign-in page, public address, the admin and developer accounts and the manual sign-in
client. A fresh offline start from exactly these parts signed admin in (4_ACCEPTANCE_AND_RECOVERY\VM_SIMULATION_ADR107.txt, T4).

Checking on the VM
------------------
The normal way does every check below by itself: CONNECT_VM.cmd -> 2, then 3 (or by hand: READ_ME.txt).

To check by hand, as in the deployment report:
  cd /data/tmrkz-incoming
  sha256sum -c tmrkz-images.tar.parts.sha256              # every part: OK
  cat tmrkz-images.tar.part-* > tmrkz-images.tar          # the single file again (needs 1.1 GB free)
  sha256sum -c tmrkz-images.tar.sha256                    # tmrkz-images.tar: OK
  sudo docker load -i tmrkz-images.tar
  for img in tmrkz/keycloak:26.7.5-2 tmrkz/folder-backend:1 tmrkz/folder-web:1; do
    sudo docker image inspect "$img" --format '{{.RepoTags}} => {{.Os}}/{{.Architecture}} id={{.Id}}'
  done
  # expected: linux/amd64 three times, and an id from the table above
  rm -f tmrkz-images.tar                                  # the joined copy is no longer needed

Then start as usual: cd /data/TMRKZ && sh start.sh (it checks the processor of every image before starting).
Data and volumes are kept: no "docker compose down -v", no volume deletion, no database re-initialisation.
