## 2. الصلاحيات بعد ADR-078

| قبل | بعد |
|---|---|
| «طلب تمركز أولي» | أُلغي. التمركز الأول يتم من «تهيئة المواقع» فقط |
| «طلب منطقة انتشار» و«طلب إعادة التمركز» | صلاحية واحدة |
| «استثناء مسافة الانتشار» | ليست صلاحية. يُعلَّم الطلب «يتجاوز المسموح»، ويقرره المعتمد النهائي: اعتماد، أو رفض، أو إرجاع للتعديل |
| قرارات المؤقت الأربعة | ليست صلاحيات. يبدأها مقدم الطلب، ويقررها المعتمد النهائي الأقرب، ولا يقرر من بدأ الإجراء |
| «إدارة المرافق» و«ربط الوحدات بالمواقع» | ضمن «معتمد عمليات الوحدة» في نطاقه، ويملكها «مدير النظام» في كل النظام |
| «تصحيح التمركز» | للتهيئة فقط، أي «مدير النظام» |
| «إعادة إرسال أحداث التمركز» | ضمن «مدير النظام» |
| أدوار المرافق القديمة الخمسة والأدوار المكررة الثلاثة | أُفرغت وسُمّيت «غير مستخدم»، وأُنهيت منحها |

أعمدة «إدارة الصلاحيات والوحدات» بالترتيب:

1. مقدم الطلب
2. معتمد السلسلة الهرمية
3. معتمد عمليات الوحدة
4. المعتمد النهائي
5. تحديد وحدات العلم
6. للعلم
7. تفعيل التمركز
8. متابعة الموقف العملياتي
9. مدير صلاحيات الوحدة
10. معتمد طلبات الصلاحية

## 4. لتكملة العمل من جهاز آخر

1. اسحب الفرع: `git pull` على الفرع `main`.
2. **تشغيل :8088 على هذا الجهاز وضع معزول (offline).** يكفي: `TMRKZ_OFFLINE=1 TMRKZ_BUILD=1 sh ops/local/up.sh`. لا تستخدم `up.sh` العادي، فهو يعيد إنشاء الشبكة المعزولة فيوقف التطبيق.
3. **في `.env` إعدادات `TMRKZ_MANUAL_LDAP_*` للآلة الافتراضية:**
   - مسار ملف الوسيط وبوابته موجودان داخل الآلة الافتراضية، لا على هذا الجهاز.
   - لذلك نُشر الخادم هنا بهذه القيم فارغة في بيئة الأمر.
   - النتيجة أن الإدخال اليدوي لغير admin وdeveloper يذهب إلى الدليل المحلي.
4. **بعد إنشاء Keycloak جديد:** شغّل `sh ops/keycloak/set-platform-password-client.sh tmrkz-mover`.
