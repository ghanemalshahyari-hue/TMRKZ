# TMRKZ — برومبت تنفيذ المكونات الإدارية للإنتاج

التاريخ: 29 أكتوبر 2026 — النطاق: المرافق والحجوزات والموارد البشرية والهوية والصلاحيات والتوقيع والموافقات الإدارية.

## النطاق الصريح

هذا التكليف لإدارة المرافق والطلبات الإدارية العامة. لا يتضمن تخطيط الانتشار العسكري أو تحسين تمركز الوحدات أو تقييم ملاءمة الأرض لمواقع عملياتية أو تحديد مسافات تكتيكية أو مواقع رئيسية وبديلة. لا تضف هذه الوظائف أو تطلب بيانات عملياتية لتنفيذها.

المستودع المستهدف: https://github.com/ghanemalshahyari-hue/TMRKZ

مرجع التوافق الإداري للموارد والهوية والتشغيل، للقراءة فقط: https://github.com/ghanemalshahyari-hue/mover

## 1. المهمة وطريقة التنفيذ

أنت مسؤول عن إكمال المكونات الإدارية للتطبيق الموجود، إلى مستوى إنتاج مثبت بالاختبارات والأدلة. لا تبدأ مشروعًا بديلًا ولا تستبدل ما بُني. هناك تطبيق فعلي وملفات تصور ومواصفات يجب الحفاظ عليها.

اعمل باستمرار داخل النطاق المصرح، دون انتظار تأكيد على القرارات التنفيذية الروتينية. إذا نقصت شهادة أو بيانات اتصال أو تجهيز لدى المؤسسة، سجل عائق الربط المحدد، وأكمل جميع الأعمال المستقلة عنه. لا تختلق اتصالًا أو شهادة، ولا تجعل نجاح المحاكاة نتيجة قبول للإنتاج.

يوجد مسار تشغيل إنتاج واحد. أزل من حزمة الإنتاج تبديل المستخدمين التجريبي، والدخول المحلي البديل، وتهيئة بيانات المثال، وأي تحويل تلقائي إلى مصادر وهمية. تبقى بيانات الاختبارات وعوازلها في بيئة اختبارات منفصلة، ولا تصبح اختيارًا في واجهة المستخدم أو في إعداد تشغيل المؤسسة.

قبل أي تعديل:

1. اقرأ AGENTS.md إن وجد، وCLAUDE.md، وhandoff/، وdocs/STATUS.md، وdocs/TRACEABILITY.md، وdocs/ARCHITECTURE_DECISIONS.md.
2. افحص الحالة المحلية والفروق والتاريخ وorigin/main. حافظ على العمل غير المحفوظ ولا تستخدم reset أو stash لإزاحته.
3. اعمل على main في نسخة العمل المعتمدة، دون فروع أو worktrees جديدة.
4. لا تعدل مشروع mover أو قواعده أو حاوياته أو بياناته. استخدامه هنا مرجع قراءة فقط.
5. لا تنسخ ملف .env أو كلمات المرور أو شهادات المفاتيح الخاصة أو بيانات الأشخاص إلى Git أو التقارير أو صور الاختبار.
6. احترم موافقات المستودع وخطافات الحماية. لا force-push ولا تجاوز للحماية. حضر التغييرات والأدلة قبل أي موافقة لازمة.

المرجع الذي راجعته هذه الحزمة:

- TMRKZ: 0fa1dbadb7eaa4e6db9977c7c94a1f617b97d0f3.
- mover: 247d6a9d0fffa4a7b8abf6532bd58252029292c2.

هذه نقاط مرجعية وليست أمرًا بالرجوع إلى إصدار أقدم. افحص أحدث الحالة قبل التنفيذ.

## 2. القرارات الإدارية المثبتة

| المجال | القرار |
|---|---|
| مصدر الجهات والأشخاص | نفس Oracle Views المعتمدة في تنقل، من خلال موصل قراءة فقط ومتوافق مع عقد الأعمدة المنشور هناك |
| مصدر المواقع | يديرها TMRKZ، مع واجهة ربط اختيارية بسجل مواقع خارجي معتمد؛ الربط لا يشمل بيانات حركة أو عمليات |
| المزامنة | كل ساعة، مع منع تداخل التشغيل وسجل نجاح وفشل وآخر تحديث ناجح |
| معرفات المصدر | ثابتة؛ عرض معرفات Oracle الخام وتشخيص الربط لمدير النظام أو المطور المخول فقط |
| بيانات HR الأساسية | مرجعها Oracle؛ الإضافات المحلية منفصلة ولا تُكتب فوق المصدر |
| مسؤولية المرافق | بناءً على صلاحية تشمل جهة محددة أو شجرتها أو مجموعة جهات مسموحة |
| بيانات الحدود | استيراد GIS أو رسم من مستخدم مخول، مع تحقق ومراجعة وإصدارات |
| الحجز الرئيسي والفرعي | علاقة المنع أو المشاركة مهيأة لكل مورد، وليست قاعدة جامدة لجميع المواقع |
| المشاركة | يمكن أن تشترك جهات متعددة في الموقع؛ لا يوجد حد سعة افتراضي مصطنع |
| مدد الاستخدام | ساعات أو أيام أو مدة مفتوحة حتى إجراء إداري معتمد ينهيها |
| الصلاحيات | أفعال مستقلة ونطاقات قابلة للجمع وفق سياسة الدور |
| مدير النظام | إدارة الإعدادات لا تمنحه تلقائيًا حق الاطلاع أو الاعتماد؛ يجوز منحه الحقوق الإدارية المناسبة صراحة |
| اعتماد مقدم الطلب | مسموح إذا كان يمتلك صلاحية الاعتماد الفعلية للمرحلة والجهة والمورد ضمن نطاقه |
| الهوية والصلاحيات | Keycloak مع LDAP، وOpenFGA |
| التوقيع | توقيع رقمي بشهادة وختم إلكتروني قابلان للتحقق |
| الشبكة | شبكة داخلية مركزية دون حاجة للإنترنت؛ LDAP داخلها |
| الحجم | نحو 7,000 جهة و200,000 سجل شخص؛ الرقم لا يعني 200,000 جلسة متزامنة |
| التزامن | ابدأ بقياس 20 مستخدمًا متزامنًا، ثم اختبر 50 كهامش استكشافي، دون اعتباره سقفًا أو قبول سعة نهائيًا |

## 3. التوافق مع تنقل: إعادة استخدام العقد، لا نسخ التطبيق

راجع في نسخة mover المعتمدة الملفات التالية حسب إصدارها الفعلي:

- app/oracle_integration.py: الاتصال، إعداداته، التحقق من القراءة فقط، والمهل.
- app/hr_mirror.py: عقد المصدر، قراءة الأعمدة، المرآة، النشر الذري، وحماية الانخفاضات أو المصادر الناقصة.
- app/hr_mapping.py وapp/hr_organisation.py وapp/hr_people.py: إصدارات التعيين وإسقاط المصدر على الجهات والأشخاص.
- app/auth/ldap_service.py وapp/auth/identity_link.py وapp/auth/oidc.py: مطابقة الهوية والربط بالمصدر.
- app/hr_access.py وapp/effective_access.py: حدود الإدارة بالجهة والشجرة، دون نقل منطق الطلبات العملياتية.
- app/templates/auth/login.html وملفات العلامة المعتمدة: التكوين البصري وصفحة الدخول.
- compose.yaml وDockerfile وscripts/sync_hr_mirror.py: نمط الإعدادات والمجلدات والمزامنة.

احتفظ بمذكرة توافق تصف: الجزء المستخدم، ملف المصدر، إصدار المرجع، سبب التكييف، والاختبار المثبت له. لا تضع نصوصًا حساسة من المستودع الخاص في المستودع العام.

TMRKZ حاليًا Java/Spring، وتنقل Python/Flask. أعد تنفيذ عقد القراءة والتطبيع نفسه بموصل مناسب للتطبيق الحالي؛ لا تضف خادم Flask كاملًا لمجرد نقل الاتصال، ولا تدع توافق Oracle يفرض نقل إطار تشغيل تنقل إلى TMRKZ.

تمييز مهم: إعدادات Oracle في تنقل ليست كلها متغيرات بيئة؛ يوجد سجل إعدادات محفوظ ومشفر وعقد أعمدة بإصدارات. افحص هذه الآلية بدل اختراع ORACLE_USER أو اسم View أو عمود من الذاكرة. لا تحاول استخدام قيمة مشفرة بمفتاح تنقل داخل التطبيق الجديد؛ رحّل الإعدادات المعتمدة عبر قناة تشغيل آمنة وأعد حمايتها بمفتاح TMRKZ.

## 4. قراءة Oracle والمزامنة كل ساعة

أنشئ HrSourceAdapter بعمليات: اختبار الاتصال، قراءة Metadata، فحص العقد، قراءة الجهات على دفعات، قراءة الأشخاص على دفعات، وإنتاج نتيجة تشغيل موحدة.

- حساب Oracle يملك SELECT على الـViews المعتمدة فقط، بلا صلاحيات كتابة.
- استخدم معاملة قراءة فقط، ومهل اتصال واستعلام، وحدود موارد وتدفق دفعات.
- أسماء الـViews والأعمدة تُتحقق من Metadata وقائمة المصدر المعتمدة؛ لا تضع مدخلات المستخدم في SQL حر.
- حافظ على المعرفات الأصلية ونطاق المصدر. لا تستخدم اسم الشخص أو اسم الجهة أو موقع الصف كمعرف.
- أعد استخدام التعيين المعتمد للأعمدة. أي بدائل لأسماء الأعمدة تُحسم بواسطة Metadata وعقد منشور، وليس بالتخمين.
- اقرأ فقط حقول الهوية والانتماء والحالة والمنصب المطلوبة. لا توسع الاستيراد إلى بيانات صحية أو جوازات أو بيانات حساسة أخرى.
- حمّل إلى staging، ثم تحقق من المفاتيح والتكرار والعلاقات والأبناء والأيتام والدورات والحالات والأعداد.
- ارفض النتيجة الفارغة أو الانخفاض الكبير غير المفسر، واحتفظ بآخر نسخة صالحة. اجعل عتبة الحماية مهيأة، وابدأ من سياسة تنقل المعتمدة بعد التحقق منها.
- انشر النسخة الجديدة في معاملة ذرية أو بتبديل snapshot موثق. القارئ يرى نسخة مكتملة واحدة.
- سجل الفشل بصورة مستقلة تبقى بعد rollback، دون صفوف أشخاص في السجلات.
- جدولة 3600 ثانية مع قفل موزع، ووقت أقصى للتشغيل، وعدم تداخل نسختين عند إعادة تشغيل العامل.
- إذا تجاوزت المهمة موعدها، لا تبدأ نسخًا متراكبة. سجل تشغيلًا مؤجلًا وأكمل من آلية آمنة.
- تعرض لوحة الإدارة آخر نجاح، عمر البيانات، المصدر وإصدار التعيين، أعداد السجلات، المدة، الأخطاء، والتشغيل التالي.
- يوجد زر تحديث يدوي مخول يستخدم مسار العمل نفسه؛ لا يشغّل عملية ثانية متزامنة.
- تعطل Oracle لا يمسح البيانات أو يمنح صلاحيات جديدة. طبق سياسة عمر المرآة الموثقة، واجعل تجاوز العمر مانعًا للأعمال التي تتطلب بيانات مصدر حديثة.

الأسماء والانتماء والحالة الأصلية تبقى محفوظة كما وردت. أسماء العرض المحلية، الوسوم، مسؤولية المرفق، مقاعد المسؤوليات والصلاحيات تحفظ في جداول منفصلة وتظهر باعتبارها إضافات محلية.

## 5. الأشخاص والهوية والمهام عند تغير الانتماء

افصل بين:

1. سجل الشخص المرجعي من HR.
2. هوية الدخول: issuer وsubject من Keycloak.
3. العضوية المؤرخة في الجهة والمنصب.
4. منحة الصلاحية والنطاق.
5. المهمة الإدارية ومالك المسؤولية الحالي.

اربط الشخص بهويته على مفتاح مؤسسي ثابت. تشابه الاسم ليس تطابقًا. الحسابات المكررة أو المطابقات المتعددة تدخل قائمة معالجة مخولة وتُمنع من الحصول على ربط تلقائي ملتبس.

عند نقل شخص أو تعطيله:

- أوقف المنح القديمة غير الصالحة، وحدّث أهلية الجلسات والأفعال في الخادم.
- لا تنتظر انتهاء JWT طويل حتى تسحب حقه في الاعتماد أو التصدير.
- انقل المهام المفتوحة إلى شاغل المنصب أو مقعد المسؤولية إذا وجد بديل واحد نشط ومخول ضمن النطاق.
- عند عدم وجود بديل أو وجود أكثر من مرشح، أحلها إلى مسؤول صلاحيات الجهة ليختار من قائمة مخولة.
- طبّق النقل على المهام المفتوحة، مع إشعار وتدقيق وسجل مالك سابق وجديد وسبب.
- قرارات الشخص السابقة وتوقيعاته لا تُنسب إلى البديل ولا تُعاد كتابتها.
- وصوله التاريخي يخضع لصلاحية العرض الحالية والسياسة المعتمدة؛ لا تجعل كونه منشئ الطلب سابقًا تجاوزًا دائمًا لسحب الوصول.

التفويض محدد المدة والفعل والنطاق، ولا يتجاوز صلاحيات المفوّض. إلغاؤه يسري على الطلب التالي داخل الجلسة نفسها.

## 6. دخول Keycloak وربط LDAP

استخدم OIDC Authorization Code مع PKCE، وربطًا ثابتًا لهوية الشخص. اعرض صفحة الدخول من Keycloak بموضوع بصري محلي مستوحى من تنقل.

- LDAP مصدر التحقق من كلمة المرور. لا تستورد كلمات المرور ولا تحفظها في TMRKZ.
- federation في وضع لا يكتب بيانات المستخدم إلى LDAP ما لم يوجد تكليف منفصل.
- تحقق TLS وثقة الشهادات إلزامي في مسار المؤسسة. لا تنقل إعدادات سماح الاتصال غير الآمن من تنقل إلى الإنتاج.
- طبّق المهل، وقفل المحاولات، والجلسات المحدودة، والخروج، وإعادة التحقق للأفعال الحساسة.
- لا تعتبر وجود LDAP وحده دخولًا تلقائيًا SSO؛ اعرض هذا الخيار فقط إذا كانت آليته المؤسسية مهيأة ومختبرة.
- أزل auth/demo-switch وauth/demo-users من حزمة الإنتاج، واختبر رفض الوصول إليهما.
- لا يمنح امتلاك حساب LDAP صلاحيات أعمال تلقائيًا؛ العضوية وحالة HR والمنح الفعلية هي الأساس.
- فشل موفر الهوية ينتج رسالة واضحة وحالة تشغيل، دون فتح دخول بديل صامت.

صفحة الدخول:

- اتجاه عربي RTL، خلفية هادئة، درجات بيج وذهبي، حقول واضحة، رسالة خطأ مفهومة، وإظهار كلمة المرور كخيار.
- استلهم تنقل: اللون الذهبي #b8975a، لون النص #2e2618، وخلفية #fdfbf6، ثم تحقق من التباين.
- استخدم اسم TMRKZ وعلامته؛ لا يظهر اسم تنقل على أنه اسم التطبيق الجديد.
- ملفات الخط والشعار والخلفية محلية ومعتمدة، دون CDN.
- الحركة اختيارية وتحترم reduced-motion، مع صورة ثابتة بديلة محلية.
- موضوع Keycloak قابل للترقية ولا يعدل ملفات الحاوية أثناء التشغيل.

## 7. استوديو الصلاحيات وOpenFGA

المكتبة محرك قرار، وليست استوديو إدارة جاهزًا للمؤسسة. ابن واجهة عربية فوق خدمة سياسة موحدة، مع نموذج OpenFGA منشور ومختبر.

الأفعال المستقلة على الأقل:

VIEW، VIEW_SUMMARY، CREATE، EDIT، REVIEW، APPROVE، EXPORT، EXECUTE، MANAGE_FACILITIES، MANAGE_ACCESS، CONFIGURE، AUDIT، VIEW_SOURCE_IDENTIFIERS.

لا تستخدم CREATE بدل EDIT. لا تجعل إخفاء زر بديلًا عن فحص الخادم.

النطاقات:

- الجهة نفسها.
- الجهة وشجرتها التابعة.
- مجموعة جهات صريحة، مع خيار ضم أبناء كل جهة.
- موقع أو شجرة مواقع.
- مورد بعينه.
- تقاطع الجهة والموقع.
- نطاق شامل ممنوح صراحة.

إذا احتوت المنحة الواحدة قيد جهة وقيد موقع، فالافتراض تقاطعهما AND. يسمح الاستوديو بسياسة OR صريحة مع معاينة أثرها. تُجمع المنح المستقلة لنفس الفعل، مع احترام أي منع صريح مهيأ. لا تجمع صلاحية فعل من منحة مع نطاق غير متعلق به من منحة ثانية لتوسيع الوصول.

يتضمن الاستوديو:

- أدوار ومسودات وإصدارات ومصفوفة أفعال.
- اختيار شجري lazy-loaded وبحث في الأبناء.
- نطاقات قابلة للفهم بصياغة عربية، ومدد وتفويضات.
- معاينة: ماذا يستطيع هذا الشخص أن يرى أو يفعل؟ ولماذا وفق السياسة المنشورة؟
- اختبار مستخدم وجهة ومورد قبل النشر، مع مقارنة أثر الإصدار.
- نشر مخول وسجل تغيرات وتراجع إلى إصدار صالح بإجراء مسجل.
- قيد يمنع مسؤول جهة من منح صلاحيات أو نطاقات خارج سلطته.
- فصل إدارة النظام عن عرض محتوى الطلبات. يجوز للشخص امتلاك الدورين بمنح صريحة.
- إخفاء معرفات HR الخام من استجابات المستخدم العادي ومن البحث والتصدير. استخدم معرفات تطبيق معتمة حيث تحتاج API إلى تعريف السجل؛ إخفاء الرقم على الشاشة لا يغني عن منع الحقول في الخادم.

اعتماد مقدم الطلب مسموح وفق القرار الجديد إذا كانت منحة APPROVE تنطبق على المرحلة والجهة والمورد والوقت. لا تتجاوز ترتيب المراحل، وسجل أن المعتمد هو مقدم الطلب. عدل اختبارات المنع المطلق القديمة وأضف اختبارًا يسمح بالحالة المخولة ويرفض غير المخولة.

مصدر المنح وعضوياتها في قاعدة الأعمال، مع transactional outbox لتحديث tuples. ثبّت authorization model id لكل إصدار سياسة. عند الإلغاء أو النقل، امنع الأفعال الحساسة إذا لم تتأكد من تطبيق أحدث إصدار المنح. فحص HIGHER_CONSISTENCY يساعد على تجاوز cache، لكنه لا يصلح تأخر مزامنة tuples بذاته.

عند تعطل OpenFGA أو عدم اكتمال مزامنة صلاحية مطلوبة، ارفض الفعل المتأثر برسالة خدمة واضحة؛ لا ترجع إلى منطق يسمح تلقائيًا.

افحص العرض والبحث والأعداد والخرائط والمرفقات والتقارير والتصدير والتحديثات بنفس السياسة. لا ترسل الحقول المحجوبة إلى المتصفح.

## 8. بيانات المرافق والخرائط الإدارية

احتفظ بشجرة الجهات مستقلة عن شجرة المواقع والموارد. لكل موقع معرف دائم، ومسؤوليات مؤرخة، وحدود بإصدارات، ومصدر بيانات واضح. يسمح بربط مواقع من سجل خارجي عبر عقد API محدود ومخول، دون الوصول المباشر إلى قاعدة تطبيق آخر.

أضف PostGIS بترحيل يحفظ البيانات الموجودة:

- geometry version من نوع Point أو Polygon أو MultiPolygon وفق حاجة السجل.
- المصدر، CRS الأصلي، النسخة الأصلية، الحدود المطَبّعة، المنشئ، الحالة، ونسخة الاعتماد.
- اقترح EPSG:4326 للتبادل والتخزين الهندسي الموحد وEPSG:3857 لعرض الخلفيات، مع سياسة واضحة لترتيب المحاور.
- افحص CRS عند الاستيراد، وحوّل بواسطة أدوات موثقة. لا تخمن CRS المفقود من شكل الأرقام.
- رفض CRS غير المدعوم أو geometry غير صالحة مع تقرير قابل للإصلاح.
- لا ترسم مضلعًا ثابت الإزاحة حول كل نقطة وتقدمه كحد موقع.
- احتفظ بالمواقع الرئيسية والفرعية على الخريطة والإشغال، بما فيها المواقع التي parent_id لديها فارغ.
- اربط الطلب بالإصدار الذي راجعه المعتمد. تعديل سجل الموقع لاحقًا لا يغير مستندًا سبق توقيعه.

دعم الخرائط عبر قائمة صيغ واختبارات معلنة، وليس ادعاء فهم أي ملف:

- GeoJSON وKML وShapefile ZIP وGeoPackage للاستيراد وفق وحدات التحويل المثبتة.
- صور Raster مرجعة جغرافيًا عبر مسار تحويل معتمد.
- PMTiles وMBTiles وحزم XYZ محلية للخلفيات، حسب موصل العرض والتقديم المنفذ.
- الطرق والصور الجوية ومخططات المرافق من بيانات متاحة ومرخصة فقط.
- manifest لكل حزمة: المصدر والترخيص والنطاق وCRS والإصدار والتاريخ وchecksums.
- مدير الخرائط يرفع حزمة أو يستورد من مصدر معتمد، ويراجعها قبل تفعيلها.
- أي تنزيل من الخادم مقيد بمصادر مسموحة، مع حدود حجم وفحص أرشيفات ومنع path traversal وSSRF.
- أصول العرض والتحويل وقواعد الإحداثيات وملفات الشبكات اللازمة متاحة محليًا.

للرسم الإداري، احتفظ بـLeaflet الحالي وأضف Leaflet-Geoman Free للوظائف المتاحة فيه بعد التحقق من الترخيص. لا تفترض أن الميزات المعلمة Pro مجانية. اختبر التحديد والرسم وتعديل الرؤوس والتراجع والإلغاء والتحقق والحفظ. يمكن إضافة OpenLayers لاحقًا بقرار موثق إذا ظهرت حاجة فعلية لا يغطيها الحل الحالي؛ لا تبدل محرك العرض لمجرد وجود مثال جاهز.

هذه أدوات تسجيل حدود المرافق وعرضها، وليست أدوات اقتراح مواقع أو توزيع أو تحليل ملاءمة عملياتية.

## 9. الطلب والحجز والموافقات

حافظ على أنواع الطلبات الإدارية الموجودة: استخدام مؤقت، استخدام مفتوح المدة، تعديل، تمديد، إلغاء، وإخلاء أو تسليم بحسب السياسة. أنواع وأسماء الحقول والنماذج ومساراتها مهيأة، دون إضافة أنواع عملياتية خارج نطاق هذه الحزمة.

- يبدأ الطلب من الخريطة أو القائمة أو زر تقديم، مع مسار تحقق واحد.
- اختيار الجهة مقيد بالنطاق المستورد. تعرض مرافقها ومسؤولياتها المرتبطة دون خلط التبعية التنظيمية بعلاقة الاستخدام.
- يسمح بطلب موارد متعددة وجهات مشاركة وفق إعداد نوع الطلب.
- الطلب المقدم لا ينشئ حجزًا حصريًا. يظل برتقاليًا بوصفه قيد المراجعة.
- الاعتماد النهائي فقط يثبت الحجز، بعد إعادة التحقق من الإتاحة والفترة والصلاحية والإصدار والتوقيع.
- الفترات UTC، والعرض Asia/Dubai، وبحدود [start,end).
- المدة المفتوحة تستخدم نهاية غير محددة، وليس تاريخًا بعيدًا مصطنعًا.
- لكل مورد سياسة مشاركة أو حصرية، وعلاقة مهيأة بين حجز الأب والأبناء.
- الموقع المشترك يمكن أن يضم موارد فرعية مستقلة. عدم وجود حد أشخاص لا يعني السماح بتعارض حجز مورد حصري.
- لا تضف سقف سعة لم يطلبه المالك؛ اجعله اختيارًا معطلًا افتراضيًا للمورد المشترك.
- تستمر السجلات السابقة، والإنهاء أو التمديد أو التعديل يترك أثرًا مؤرخًا مستقلًا.
- حالات الاستخدام والتسليم والإغلاق منفصلة عن قرار الاعتماد. مهام الاستلام والتسليم مهيأة بأصحابها ومددها.

أكمل استوديو النماذج والتدفقات:

- محرر مرئي لشروط الظهور والإلزام ومراحل التدفق والتفرع وأثر تغيير الحقول.
- لغة قواعد محددة الأنواع ومحدودة العمليات. لا eval ولا JavaScript أو SQL يكتبه المدير.
- تسلسل وتوازٍ ALL/ANY، ومهل وتنبيهات ومسار مسؤولية واضح.
- مسودة ثم تحقق ثم محاكاة ثم نشر إصدار ثابت.
- الطلبات الجارية تبقى على إصداراتها، وترحيلها يحتاج إجراءً صريحًا وسجلًا.
- الإرجاع والرفض يحتاجان سببًا؛ يستمر تاريخ النسخ والقرارات.
- جهات للعلم بعد الاعتماد، مع تحقق وصول مستقل ودون منح المرفقات تلقائيًا.

## 10. التوقيع الرقمي والختم الإلكتروني

استخدم DSS كمرشح Java مفتوح المصدر للإنشاء والتحقق بصيغ مثل PAdES، مع تثبيت إصدار متوافق وترخيص LGPL-2.1. المكتبة ليست شهادة ولا مزود ثقة ولا HSM.

جهز تكاملًا بمزود المؤسسة: توقيع الشخص بشهادته، وختم الجهة بشهادة منفصلة، وحفظ المفاتيح لدى مزود أو جهاز مخول. إعادة إدخال كلمة مرور LDAP وصورة ختم لا تستبدلان ذلك.

يتضمن المستند رقم الطلب وإصداره والجهة والموارد والفترة ونسخ الحدود والقرار وصفة المعتمد. تحفظ الشهادات وسلسلة الثقة وإثبات التوقيع ونتيجة التحقق.

حدد آلية الختم الزمني ومعلومات الإلغاء CRL/OCSP داخل الشبكة، وسياسة صلاحية مواد التحقق وتحديثها. إذا طلب مستوى ثقة معتمد في الإمارات، تحقق من خدمات المزود وسياسته مقابل UAE Trusted List وإرشادات TDRA؛ استخدام DSS وحده لا يثبت هذا المستوى.

التكامل الخارجي مع HSM/TSA لا يدخل في معاملة قاعدة البيانات نفسها:

- جمّد نسخة المستند وبصمتها أثناء إجراء التوقيع.
- اجعل مهمة التوقيع idempotent ومربوطة بالشخص والإصدار.
- بعد التحقق، أعد فحص الصلاحيات والإصدار والإتاحة داخل معاملة القرار والحجز وFlowable والتدقيق وoutbox.
- عند تعارض حجز أو تغير نسخة، لا تنشر مستندًا يوحي بأن الحجز اعتمد، وسجل محاولة التوقيع غير المنشورة بصورة صحيحة.
- انقطاع المزود يوقف الاعتماد المتأثر دون حجز جزئي أو fallback إلى HMAC.
- المستند النهائي يُتحقق من توقيع الشخص وختم الجهة فيه، مع حفظ صلاحية التوقيعات السابقة عند الإضافة.

أظهر إعداد المزود وحالته ونقص الشهادات بوضوح. لا تطلب المفاتيح الخاصة في المحادثة أو تضعها في Git.

## 11. تصميم الواجهة المقترح

الترتيب الافتراضي: «الخريطة مع لوحة سياقية». يوجد تطبيق واحد، وتختلف الأدوات حسب صلاحية المستخدم، لا حسب وضع تجريبي أو إنتاج.

تسلسل المستخدم:

1. يحدد جهة من شجرة مفهومة أو يبحث باسم المرفق.
2. يختار المرفق على الخريطة أو من قائمة مرتبطة بها.
3. تظهر لوحة جانبية: الاسم، التبعية الإدارية، فترة الإتاحة المختارة، والسجل المسموح.
4. زر واضح «طلب استخدام» يفتح نموذجًا جانبيًا قصيرًا: البيانات، الموارد والفترة، المرفقات، ثم الملخص.
5. قبل الإرسال يرى المستخدم ما اختاره، ومسار المراجعة، والتحذيرات الفعلية.
6. يتابع الحالة من الطلب نفسه، مع مراجعة وتوقيع واستلام وتسليم حسب دوره.

بدائل ترتيب الشاشة للمقارنة:

| التصور | الترتيب | الاستخدام |
|---|---|---|
| الخريطة مع لوحة سياقية — الموصى به | الخريطة هي المساحة الأكبر، وشجرة مطوية ولوحة تظهر عند الاختيار | المستخدم اليومي واختيار المرفق |
| خطوات واضحة | خطوات قصيرة ونموذج بجوار خريطة سياقية ثابتة | الطلبات التي تتطلب بيانات ومرفقات كثيرة |
| مكتب المراجعة | قائمة مهام وملخص مستند، مع خريطة سياقية عند الحاجة | المراجع والمعتمد |

استخدم التصور الأول كأساس، ويمكن أن تكون الخطوات ومكتب المراجعة شاشات متناسقة داخله. لا تلزم المستخدم بفهم شجرة كاملة أو أسماء تقنيات.

- الأزرار مكتوبة، والإجراءات الأساسية ظاهرة.
- يمكن وجود قائمة سياقية مختصرة عند اختيار المرفق، مع نفس الإجراءات في اللوحة الجانبية.
- أي سحب أو رسم له بديل بالنقر أو إدخال الإحداثيات، وتعمل الأدوات بلوحة المفاتيح.
- اللون يرافقه وصف ورمز: قيد المراجعة، معتمد، مشغول؛ لا تعتمد على اللون وحده.
- لا تعرض خريطة خالية دون شرح سبب نقص الحزمة أو الصلاحية.
- ابحث في شجرة الجهة المسموحة كلها، مع تحميل تدريجي، ولا تحمل 200,000 شخص في المتصفح.
- المعرّفات الخام ورسائل التوصيل التقنية تظهر للمخولين فقط.
- نسخة الهاتف تحافظ على الاختيار والطلب وتمنع التداخل الأفقي.

## 12. قاعدة البيانات والترحيل

طوّر مخطط التطبيق الحالي بهجرات مستقلة، ولا تعدل V1 المطبق على قواعد قائمة. افصل مالك الترحيل عن مستخدم التشغيل.

كيانات الحد الأدنى:

| مصدر HR | hr_source، hr_mapping_version، hr_sync_run، hr_snapshot، hr_unit، hr_person، hr_sync_issue |
| الإسقاط المحلي | organization، person، identity_link، membership، position_seat، local_metadata |

الحالات المحفوظة لا تستبدل سجل التاريخ. فهارس المفاتيح والجهة والحالة والفترات والهندسة محددة من الاستعلامات الفعلية. القيود تمنع الدورات والمفاتيح اليتيمة والتعارضات والكتابة على النسخ المنشورة.

اجعل الترحيل من الإصدار الموجود قابلًا للاختبار، واحفظ الحجوزات والمرفقات والقرارات. لا تشغل ترحيلات TMRKZ على قاعدة تنقل أو على Oracle HR.

## 13. واجهات الخادم والتكامل

حافظ على عقد API القائم حيث أمكن، مع ترحيل موثق للعميل عند تغييره. أضف مجموعات واضحة:

- الهوية: جلسة التطبيق وOIDC والخروج وحالة الربط.
- HR: إعداد مصدر مخول، فحص العقد، معاينة التعيين، تشغيل المزامنة، الحالة والقضايا.
- الجهات والأشخاص: أبناء شجرة وصفحات بحث ومرشحات نطاق، دون حقول المصدر المحجوبة.
- الوصول: مسودات أدوار ونطاقات ومحاكاة وأثر ونشر وتفويض وإلغاء.
- المرافق والخرائط: سجل المواقع والموارد، نسخ الحدود، استيراد الحزم وحالتها.
- الطلبات: إنشاء وتحرير وتقديم وإرجاع ورفض ومراجعة وإجراءات الفترة.
- الإتاحة: تحقق من نطاق كل مورد في الخادم قبل حساب أو إرجاع الإتاحة أو أسماء الموارد أو أعداد الطلبات.
- التوقيع: معاينة نسخة مجمدة، بدء توقيع، حالة مهمة، مستند نهائي، وتقرير تحقق.
- التنفيذ الإداري: تسليم واستلام وإغلاق.
- التقارير والتدقيق والتصدير: نطاق وحقوق حقول وإعادة تحقق عند تنزيل الملف.

الأخطاء مفهومة: عدم صلاحية، نسخة قديمة، تعارض، بيانات HR قديمة، مزود غير جاهز. لا تعرض stack trace أو أسرار اتصال. المفاتيح الحساسة ونتائج الإدارة ليست في OpenAPI كأمثلة فعلية.

## 14. مواءمة متغيرات الإعداد والنشر

أعد استخدام معاني إعدادات تنقل لا قيم أسراره أو منافذه أو قاعدة بياناته. وثق أي تغيير اسم، واجعل مسار الحقن واحدًا وواضحًا.

| إعدادات المرجع | تكييف TMRKZ |
|---|---|
| LDAP_SERVER، LDAP_PORT، LDAP_BASE_DN، LDAP_DOMAIN | قيم اتصال المؤسسة في إعداد federation؛ تُحقن محليًا ولا تُكتب في المستودع |
| LDAP_BIND_DN، LDAP_BIND_PASSWORD | أسرار عبر ملفات أو مخزن أسرار، مع إخفائها من واجهات القراءة والسجلات |
| LDAP_REQUIRE_TLS، LDAP_TLS_VALIDATE، LDAP_CA_CERT_PATH | تحقق مفعل وثقة محلية؛ لا تعتمد إعداد سماح غير آمن |
| LDAP_MILITARY_NUMBER_ATTRIBUTE | اسم توافق قديم إن استُخدم؛ الواجهة تعرض «الرقم الوظيفي»، وتعيين الحقل يُراجع من المرجع |
| ORACLE_SETTINGS_KEY، ORACLE_CONNECT_TIMEOUT_S، ORACLE_CALL_TIMEOUT_MS | مفتاح حماية مستقل لـTMRKZ ومهل مقابلة للموصل الجديد |
| إعداد Oracle المحفوظ: host_or_url، port، server_name، name_type، username، query، driver_mode | نموذج إعداد معتمد وعقد قراءة؛ لا تفترض أن قيمًا مشفرة أو أوضاع مشغل Python تُنقل حرفيًا إلى JDBC |
| TNQL_HR_SYNC_INTERVAL | TMRKZ_HR_SYNC_INTERVAL_SECONDS = 3600، مع تحويل وحدة القيمة القديمة صراحة |
| OPENFGA_API_URL، OPENFGA_API_TOKEN، OPENFGA_STORE_ID، OPENFGA_MODEL_ID | خدمة وstore/model منفصلة لـTMRKZ؛ لا تعيد استخدام متجر منح تنقل |
| SESSION_IDLE_TIMEOUT_SECONDS، SESSION_ABSOLUTE_MAX_AGE_SECONDS | سياسات جلسة مقابلة في Keycloak والتطبيق، متسقة ومختبرة |
| TNQL_PUBLIC_URL، TNQL_WEB_PORT، MOVER_HOST، MOVER_HTTPS_PORT | TMRKZ_PUBLIC_URL وTMRKZ_HTTP_PORT وTMRKZ_HTTPS_PORT؛ احتفظ بمنفذ التطبيق الحالي المخصص أثناء القبول وتجنب منافذ تنقل |

لا تنقل SECRET_KEY الخاصة بـFlask كما هي إلى مفهوم مفتاح جلسة Java أو إلى مفاتيح Keycloak. لكل مكون أسراره الخاصة وخطة تدوير.

التشغيل:

- مشروع Docker باسم مميز مثل tmrkz؛ لا يستخدم اسم mover ولا مجلداته أو وحدات تخزينه.
- خدمات التطبيق والواجهة، PostgreSQL/PostGIS، Keycloak، OpenFGA، عامل HR، عامل outbox والتوقيع، وعكس TLS داخلي.
- قواعد أو صلاحيات بيانات منفصلة للأعمال والهوية والصلاحيات؛ لا حساب schema owner للتشغيل.
- أسماء صور مباشرة ومميزة مثل tmrkz/backend:version وtmrkz/web:version مع manifest يثبت digests.
- لا تبنِ الصور داخل البيئة المعزولة. تُنقل صور وإصدارات واعتماديات كاملة ومتحقق منها، وتعمل دون pull عند التشغيل.
- runtime غير root، وصلاحيات ملفات محدودة، وhealth/readiness checks، ومجلدات دائمة واضحة، وسجلات محلية بدوران.
- لا تنشر منافذ Oracle أو PostgreSQL أو OpenFGA أو لوحات الإدارة للعامة. وصول الإدارة من مسار داخلي مخول.
- TLS داخلي مع DNS وثقة صحيحة. Docker bridge وحده لا يثبت منع الخروج؛ اختبر سياسة الشبكة المضيفة.
- لا تعتمد على Vercel أو CDN أو مزود سحابي للتشغيل.
- نسخ قاعدة الأعمال والهوية والصلاحيات والمرفقات وإعدادات المصدر المشفرة بطريقة متناسقة، مع إجراء خاص لحماية واستعادة مفاتيح المؤسسة.
- نفذ استعادة على بيئة اختبار نظيفة وقارن البيانات والمرفقات وسياسات الوصول وقدرة التحقق من المستندات.

## 15. القبول واختبارات الإنتاج

لا يكفي عدد الاختبارات. أنشئ مصفوفة: قرار أو متطلب ← كود ← اختبار ← نتيجة ← دليل ← قيد متبقٍ.

اختبارات ملزمة:

1. قراءة Oracle بنفس عقد تنقل، مع إثبات عدم تنفيذ DML/DDL.
2. Metadata وتعيين أعمدة غير متوافق؛ يرفض المصدر دون تخمين أو إفساد المرآة.
3. مزامنة كاملة ثم فشل جزئي أو نتيجة فارغة أو انخفاض غير مسموح؛ تبقى النسخة الصالحة.
4. عدم تداخل تشغيلين، واستئناف آمن بعد توقف العامل، وجدولة الساعة.
5. ثبات هوية الجهة والشخص عند إعادة التسمية أو تغيير الانتماء.
6. منع تعديل حقول HR الأصلية، مع بقاء الإضافات المحلية بعد المزامنة.
7. LDAP الصحيح والخاطئ والمعطل، وTLS غير الموثوق، وغياب fallback التجريبي.
8. سحب عضوية أو تفويض داخل جلسة مفتوحة يمنع الفعل التالي والتصدير والمرفقات.
9. نقل المهام لمنصب ذي بديل وحيد، وتحويل الحالات الملتبسة إلى مسؤول مخول.
10. منحة عرض دون تحرير، وتحرير دون اعتماد، وإدارة نظام دون عرض محتوى.
11. نطاق الجهة وشجرتها والمجموعة الصريحة، وتقاطع جهة وموقع، وحدود مسؤول منح الصلاحيات.
12. فحص إتاحة لمورد خارج النطاق لا يكشف وجوده أو اسمه أو طلباته.
13. مقدم طلب لديه APPROVE الصحيح يستطيع اعتماد مرحلته، وآخر دونها يُرفض.
14. ظهور موقع رئيسي مستقل وموقع فرعي في الخريطة والإشغال.
15. استيراد حدود فعلية ورفض CRS أو هندسة غير صالحين، والحفاظ على النسخة السابقة.
16. حفظ geometry ثم إعادة فتحها، وعدم إعادة توليد شكل ثابت حول النقطة.
17. موقع مشترك وموارد فرعية مستقلة، وعلاقات منع الأب والأبناء حسب الإعداد.
18. طلب قيد الدراسة لا يحجز المورد. اعتمادان متزامنان على مورد حصري ينجح أحدهما فقط.
19. طلب متعدد الموارد يتراجع كله إذا تعارض أحدها، دون حجز أو قرار جزئي.
20. مدة مفتوحة، وفترات ساعات وأيام، وحدود الفترات وفترة التسليم.
21. نشر نماذج وتدفقات جديدة لا يغير الجارية، مع اختبار محرر الشروط من الواجهة.
22. توقيع شخص وختم جهة بشهادات تحقق حقيقية، وفشل شهادة ملغاة أو منتهية أو سلسلة غير موثوقة.
23. انقطاع مزود التوقيع أو تغير الإصدار أو حدوث تعارض بعد التوقيع؛ لا يظهر حجز أو مستند نهائي مضلل.
24. صلاحية العرض المختصر تمنع الحقول والمرفقات فعليًا، لا بإخفاء CSS.
25. بدء واستكمال رحلة الاستخدام الإداري من الواجهة وحدها، بما فيها الدخول الحقيقي واختيار الجهة والمرفق والإرجاع والتعديل والمراجعة والتوقيع والتسليم والإغلاق.
26. الاختبار السابق لا يحقن cookie أو role ولا يستدعي API بدل نقرات المستخدم لإنجاز انتقالات الرحلة. API يجوز لإعداد بيانات الاختبار فقط، مع فصل التقريرين.
27. لا اتصالات إنترنت مطلوبة أثناء الرحلة بعد منع الخروج، مع بقاء الخدمات الداخلية المعتمدة.
28. 7,000 جهة و200,000 شخص اصطناعي في بيئة حمل مستقلة، مع 20 مستخدمًا متزامنًا ثم قياس 50؛ شمل البحث والشجرة والإرسال والمراجعة والاعتماد والمرفقات، لا القراءات فقط.
29. قياس P50/P95/P99 والأخطاء وطول الطوابير والموارد، وإعلان العتاد والمدة والبيانات. لا تجعل قياسًا قصيرًا إثباتًا لتوفر عالٍ.
30. نسخ واستعادة وعودة إصدار، وهجرة بيانات من النسخة الحالية، وتحقق الصلاحيات والمستندات بعد الاستعادة.

أهداف أولية مقترحة للاختبار وليست نتائج: P95 لا يتجاوز ثانيتين للبحث والقراءات المعتادة عند 20 مستخدمًا بعد اكتمال التهيئة؛ يفصل زمن LDAP والتوقيع الخارجي في القياس ويعرض للمستخدم تقدمًا واضحًا. اختبر الاستعادة وحدد RPO/RTO المقاسَين والموافق عليهما قبل اعتماد التشغيل، ولا تخترعهما من عدد المستخدمين.

## 16. ترتيب الإنجاز دون إعادة اكتشاف المشروع

1. إصلاح نطاق فحص الإتاحة، وفصل EDIT، وظهور المواقع الرئيسية، وتثبيت الاختبارات المرتبطة.
2. ربط HR الحقيقي وعقد المزامنة، ثم Keycloak/LDAP، وإلغاء مسارات العرض التجريبي في الإنتاج.
3. OpenFGA واستوديو الصلاحيات، مع ترحيل المنح واختبارات سحب الوصول.
4. PostGIS وحدود المرافق الفعلية ومدير الخرائط والواجهة المعتمدة.
5. محرر الشروط والنماذج والتدفقات وحالات الاستخدام والحجز.
6. التوقيع والختم ومزوّد المؤسسة، مع المعالجة الصحيحة للمعاملات والإخفاقات.
7. حزمة التشغيل المعزول، والترحيل والاستعادة، ثم قبول الواجهة والحمل.

هذه مراحل تنفيذ داخل المنتج الواحد، وليست أوضاع تشغيل يختار بينها المستخدم.

## 17. ما يُسلّم في النهاية

- المصدر الكامل مع الحفاظ على ملفات التصور السابقة.
- هجرات وعقد API وإصدارات سياسة ونموذج صلاحيات واختباراته.
- مذكرة توافق تنقل وبيان مصدر كل إعداد، دون أسرار أو صفوف أشخاص.
- دليل تشغيل وتهيئة Oracle وLDAP وKeycloak وOpenFGA والخرائط والتوقيع.
- صور حاويات وحزمة معزولة وSBOM وسجل تراخيص وتثبيت إصدارات.
- إجراءات النسخ والاستعادة والترقية والعودة وإدارة المفاتيح.
- نتائج الاختبارات الآلية وقبول الواجهة وأدلة الحمل والاستعادة.
- حالة كل تكامل: مربوط ومختبر، أو محجوب بمتطلب مؤسسة محدد.
- تقرير جاهزية إنتاج قائم على الأدلة. لا تكتب «جاهز للإنتاج» إذا كانت الهوية أو بيانات المصدر أو الشهادات المطلوبة غير مربوطة أو لم تنجح اختبارات القبول.

ابدأ بما تستطيع إنجازه الآن، وسجل الافتراضات، واستمر في الأعمال المستقلة. لا تعد طرح الأسئلة الخمسة والعشرين التي أجاب عنها المالك.
